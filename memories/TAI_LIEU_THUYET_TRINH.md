# TÀI LIỆU THUYẾT TRÌNH - SERVICE RECEPTION & MOBILE APP

## I. SERVICE RECEPTION (Phiếu Tiếp Nhận Dịch Vụ)

### 1. TỔNG QUAN
ServiceReception là phiếu tiếp nhận dịch vụ điện tử do kỹ thuật viên tạo khi khách hàng đến trung tâm. Đây là bước chuyển đổi từ appointment (lịch hẹn) sang quá trình thực hiện dịch vụ.

### 2. SCHEMA - CẤU TRÚC DỮ LIỆU

#### 2.1. Thông tin cơ bản
```javascript
{
  receptionNumber: String,        // Mã phiếu: REC-YYMMDD-XXX
  appointmentId: ObjectId,        // Liên kết với lịch hẹn
  customerId: ObjectId,           // Khách hàng
  vehicleId: ObjectId,            // Xe
  receivedBy: ObjectId,           // Kỹ thuật viên tiếp nhận
  receivedAt: Date,               // Thời gian tiếp nhận
  estimatedCompletionTime: Date,  // Dự kiến hoàn thành
  estimatedServiceTime: Number    // Thời gian làm (phút)
}
```

#### 2.2. Tình trạng xe (vehicleCondition)
Ghi nhận chi tiết tình trạng xe khi tiếp nhận:

**Ngoại thất (exterior):**
- condition: "excellent" | "good" | "fair" | "poor"
- damages: [{location, type, severity, description, photoUrl}]
- types: "scratch", "dent", "crack", "rust", "paint_damage", "missing_part"

**Nội thất (interior):**
- condition, cleanliness
- damages: [{location, type, description, photoUrl}]

**Pin (battery) - Đặc thù EV:**
- level: 0-100%
- health: "excellent" | "good" | "fair" | "poor" | "replace_soon"
- temperature, chargingStatus, lastChargeDate, cycleCount

**Lốp xe (tires):**
- Cả 4 bánh + bánh dự phòng
- treadDepth, pressure, condition

**Đèn (lights):**
- headlights, taillights, indicators, interiorLights
- Status: "working" | "dim" | "not_working"

**Mileage, fluids, generalIssues...**

#### 2.3. Dịch vụ được đề xuất (recommendedServices)
Kỹ thuật viên đề xuất dịch vụ bổsung sau khi kiểm tra:
```javascript
[{
  serviceId: ObjectId,
  serviceName: String,
  category: String,            // Category của service
  quantity: Number,
  reason: String,              // Lý do đề xuất
  estimatedCost: Number,
  estimatedDuration: Number,   // Phút
  addedBy: ObjectId,           // Kỹ thuật viên thêm
  addedAt: Date,

  // Tracking hoàn thành (chỉ có 2 trường Boolean)
  isCompleted: Boolean,
  qualityCheckPassed: Boolean,

  _id: ObjectId                // Auto-generated by MongoDB
}]
```

**LƯU Ý:** Schema model có định nghĩa thêm các trường `completedBy`, `completedAt`, `actualDuration`, `technicianNotes` nhưng **KHÔNG được sử dụng trong thực tế**. DB chỉ lưu `isCompleted` và `qualityCheckPassed`.

#### 2.4. Phụ tùng yêu cầu (requestedParts)
```javascript
[{
  partId: ObjectId,
  partName: String,
  partNumber: String,
  quantity: Number,
  reason: String,

  // Trạng thái phê duyệt
  isApproved: Boolean,
  isAvailable: Boolean,
  availableQuantity: Number,
  customerApprovalRequired: Boolean,

  // Chi phí
  estimatedCost: Number,

  _id: ObjectId
}]
```

**LƯU Ý:** Schema có `shortfall`, `alternativePartSuggested`, `actualCost`, `customerApproved` nhưng **KHÔNG xuất hiện trong DB thực tế**.

#### 2.5. Phụ tùng đặt ngoài (externalParts)
Phụ tùng phải đặt từ nhà cung cấp bên ngoài (KHÔNG có sẵn trong kho):

**Flow:**
1. Technician ghi chú trong `specialInstructions` rằng cần parts ngoài
2. **Staff khi approve** sẽ thêm external parts vào reception

```javascript
[{
  partName: String,
  partNumber: String,
  supplier: {name, contact, address},
  quantity: Number,
  unitPrice: Number,
  totalPrice: Number,
  warranty: {period, description},
  estimatedArrival: Date,
  orderStatus: "pending_order" | "ordered" | "in_transit" | "arrived" | "installed",
  orderDetails: {orderNumber, orderDate, orderedBy},
  notes: String,
  addedBy: ObjectId,     // Staff ID (added during approval)
  addedAt: Date,
  _id: ObjectId
}]
```

**Trong DB thực tế:** `externalParts: []` - Schema đã implement nhưng **chưa có test data** (feature đã sẵn sàng sử dụng).

#### 2.6. Quy trình phê duyệt (submissionStatus)
```javascript
{
  submittedToStaff: Boolean,
  submittedAt: Date,
  submittedBy: ObjectId,

  staffReviewStatus: "pending" | "approved" | "rejected" |
                     "needs_modification" | "partially_approved" |
                     "pending_parts_restock",

  reviewedBy: ObjectId,
  reviewedAt: Date,
  reviewNotes: String,

  approvalDecision: {
    servicesApproved: [{serviceId, approved, reason}],
    partsApproved: [{partId, approvedQuantity, originalQuantity, reason}],
    estimatedTotalCost: Number,
    customerNotificationRequired: Boolean
  }
}
```

#### 2.7. EV Checklist
```javascript
evChecklistItems: [{
  id: String,               // e.g. "battery_soc", "charging_port"
  label: String,            // "Kiểm tra % pin (SOC)"
  category: "battery" | "charging" | "motor" | "safety" | "general",
  checked: Boolean,
  status: "good" | "warning" | "critical",
  notes: String,            // Optional
  _id: ObjectId
}],

evChecklistProgress: {
  progressPercentage: Number,
  isCompleted: Boolean,
  criticalIssuesFound: []    // Array rỗng trong DB thực tế
}
```

**Ví dụ items thực tế:**
- battery_soc: "Kiểm tra % pin (SOC)"
- battery_soh: "Tình trạng sức khỏe pin (SOH)"
- charging_port: "Tình trạng cổng sạc"
- motor_performance: "Hiệu suất động cơ"
- safety_isolation: "Kiểm tra cách điện cao thế (≥500Ω/V)"
- general_brakes: "Phanh và dầu phanh"

**LƯU Ý:** evChecklistProgress trong schema có `totalItems`, `completedItems`, `safetyItemsCompleted`, `criticalIssuesFound` (với fields chi tiết) nhưng **DB chỉ lưu** `progressPercentage`, `isCompleted`, và `criticalIssuesFound` (array rỗng).

#### 2.8. Status workflow
```
"received" → "inspected" → "approved"/"rejected" →
"in_service" → "completed" → "ready_for_pickup"
```

### 3. CONTROLLERS - XỬ LÝ LOGIC

#### 3.1. createServiceReception
**Route:** `POST /api/service-receptions/:appointmentId/create`
**Role:** technician, admin

**Logic:**
1. Kiểm tra appointment status = "customer_arrived"
2. Verify kỹ thuật viên được assign
3. Kiểm tra deposit đã thanh toán (nếu deposit_booking)
4. Validate services và parts tồn tại
5. Generate reception number: `REC-YYMMDD-XXX`
6. Tạo ServiceReception với:
   - vehicleCondition từ request
   - recommendedServices (chỉ services bổ sung, không bao gồm booked service)
   - requestedParts
   - evChecklistItems
   - Auto-submit cho staff (submissionStatus.staffReviewStatus = "pending")
7. Update appointment:
   - status → "reception_created"
   - bookingType: "deposit_booking" → "full_service" (nếu có recommendedServices)
   - serviceReceptionId
8. Sync checklist data với appointment

**NOTE QUAN TRỌNG:**
- Initial booked service KHÔNG được track trong ServiceReception (đã thanh toán)
- Chỉ recommendedServices (phát hiện khi kiểm tra) được track
- Services chỉ được add vào appointment SAU KHI staff approve

#### 3.2. approveServiceReception
**Route:** `PUT /api/service-receptions/:id/approve`
**Role:** staff, admin

**Logic:**
1. Staff review và quyết định approve/reject
2. Support modifications (staff có thể sửa services/parts)
3. Handle external parts nếu có
4. **IMMEDIATE PART REDUCTION** khi approve:
   - Giảm inventory của requestedParts (isAvailable=true)
   - Giảm inventory của commonParts trong services
   - Update currentStock, usedStock, averageUsage
5. Tính toán additional costs:
   - additionalServicesCost (từ recommendedServices)
   - additionalPartsCost (từ requestedParts)
   - laborCost
   - tax 10% VAT
6. Add services và parts vào appointment:
   - appointment.services.push(...)
   - appointment.partsUsed.push(...)
   - appointment.totalAmount += totalAdditional
7. Update appointment status → "reception_approved"
8. Nếu có externalParts:
   - appointment.hasExternalParts = true
   - appointment.externalPartsInfo
   - Cập nhật estimatedCompletion nếu staff cung cấp extendedCompletionDate
9. Detect part conflicts
10. Nếu rejected: reset appointment → "customer_arrived" để technician tạo lại

**FLOW QUAN TRỌNG:**
```
Technician đề xuất services/parts (recommendedServices)
    ↓
Staff review + approve
    ↓
Services/parts được ADD vào appointment (ONLY HERE)
    ↓
Parts inventory giảm IMMEDIATELY
    ↓
Appointment totalAmount update
```

### 5. FLOW TƯƠNG TÁC

```
1. Customer arrives → Appointment status = "customer_arrived"
   ↓
2. Technician creates ServiceReception (createServiceReception)
   - Kiểm tra xe
   - Ghi nhận vehicleCondition
   - Đề xuất recommendedServices (bổ sung)
   - Yêu cầu requestedParts
   - Complete EV checklist
   - Auto-submit cho staff
   ↓
3. Appointment status → "reception_created"
   ↓
4. Staff reviews ServiceReception (approveServiceReception)
   - Xem recommendedServices
   - Kiểm tra parts availability
   - Có thể modify services/parts
   - Có thể add externalParts
   - Approve/Reject
   ↓
5a. If APPROVED:
    - Services → appointment.services
    - Parts → appointment.partsUsed
    - Parts inventory GIẢM NGAY
    - totalAmount update
    - Appointment status → "reception_approved"
    ↓
5b. If REJECTED:
    - Appointment → "customer_arrived"
    - Technician tạo lại reception
    ↓
6. Technician bắt đầu làm việc
   ↓
7. Complete services → Generate invoice → Payment
```

## IV. ĐIỂM QUAN TRỌNG CẦN NHỚ

### ServiceReception:
1. **2-tier service tracking**:
   - Booked service (đã trả) KHÔNG track trong reception
   - Recommended services (phát hiện mới) track trong reception

2. **Immediate part reduction**:
   - Parts giảm NGAY khi staff approve (không đợi hoàn thành)

3. **Staff is gatekeeper**:
   - Services/parts chỉ add vào appointment SAU KHI staff approve

4. **External parts support**:
   - Hỗ trợ đặt parts từ supplier bên ngoài
   - Extend completion date

### Mobile App:
1. **Expo-based**: Dễ develop, deploy
2. **TypeScript**: Type safety
3. **Context API**: Simple state management
4. **AsyncStorage**: Persistent storage
5. **Role-based navigation**: Khác role khác UI

### Integration:
1. **Same API**: Web và mobile dùng chung backend API
2. **JWT auth**: Token-based authentication
3. **Socket.io**: Real-time updates cho cả web và mobile
4. **Vietnamese**: Full tiếng Việt support
